# 御兽山海（暂定名）

抖音小游戏 · 竖屏 · 山海经题材 · 放置养成 + 寻兽十连 · 纯广告变现。

> 注意：在抖音开放平台注册时选 **小游戏**，不是小程序。两者是不同的应用类型，游戏类目、广告变现和审核规则都按小游戏走。

- 设计文档：[docs/游戏设计文档.md](docs/游戏设计文档.md)
- 运营文档：[docs/运营文档.md](docs/运营文档.md)

## 美术素材

- 清单与 ChatGPT 提示词：[docs/美术素材清单.md](docs/美术素材清单.md)
- 原图上传到 `art/inbox/`（文件名用清单里的中文名），然后运行 `python3 tools/art/import.py`：自动去纯色背景、裁边、缩放压缩，放进 `client/assets/resources/skin/`，原图挪到 `art/originals/`。`--status` 只看进度。
- 界面按文件名取图（`beast_jiuweihu`、`bg_battle_nanshan` 等），缺图时显示占位，换图不用改代码。
- 立绘默认朝右。朝左的在 `beasts.json` 里加 `"facing": "left"`，战斗里我方会自动转向朝右、敌人朝左。
- 界面字体：站酷快乐体（SIL OFL 1.1，可商用），只保留游戏里用到的字，约 130KB，在 `client/assets/resources/font/yushou.ttf`。
  **改了界面文字或配置表后**运行 `python3 tools/art/font.py` 重新生成（需要 `pip install fonttools brotli`）；`npm test` 会检查有没有缺字。
  字体里没有的生僻字（狌、褢、讙、鱬 等）由同一字体的部件拼成，见 `tools/art/font_synth.py`。

## 目录结构

```
client/                         Cocos Creator 3.8 工程（用 Cocos Creator 打开这个目录）
  assets/resources/config/      配置表（JSON）：游戏和数值模拟器共用这一份
  assets/scripts/
    core/                       纯游戏逻辑：不依赖 Cocos、不依赖抖音接口，可在 Node 里单测
      systems/                  抽兽、升星、阵位、关卡与镇妖塔、挂机离线、签到
      reveal/RevealSession.ts   现身拍符的判定（按毫秒、按触摸时间戳）
      GameCore.ts               逻辑门面：界面只通过它读写游戏状态
    platform/                   平台层：抖音 tt 接口实现、浏览器调试实现、广告服务、埋点
    app/App.ts                  组装 core + platform，负责存档和前后台切换
    view/Boot.ts                Cocos 启动组件（加载配置表、驱动 App、调试面板）
tests/                          单元测试（vitest）
tools/sim/                      数值模拟器（Python 标准库）
docs/                           设计文档、运营文档
```

### 分层规则

1. `core/` 里**不能** `import 'cc'`，也不能用 `tt`。这样逻辑可以在 Node 里测试，以后换引擎或上微信小游戏只需重写 `view/` 和 `platform/`。
2. 数值**只改配置表**，不要写死在代码里。
3. 改了 `core/formulas.ts` 的公式，要同步改 `tools/sim/sim.py` 的 `Model`。`tests/formulas.test.ts` 会拿两边算出的数比对，不一致时测试失败。
4. 界面脚本放 `view/`，通过 `App.core`、`App.ads`、`App.analytics` 访问逻辑和平台；core 发出的事件（`App.core.events.on(...)`）用来刷新界面。

## 常用命令（在仓库根目录）

```bash
npm install          # 第一次
npm test             # 单元测试（含配置表校验、公式与模拟器一致性检查）
npm run typecheck    # 类型检查（core / platform / app / tests）
npm run sim          # 数值模拟：python3 tools/sim/sim.py，可加 --days 180 --seeds 20 等参数
```

改完配置表先跑一次 `npm test`：配置校验会检查兽池每档非空、概率之和为 100%、完美区不低于 70ms 等规则。

## 在 Cocos Creator 里打开

1. 打开 Cocos Dashboard → 项目 → **导入**，选择仓库里的 `client/` 目录。第一次打开会生成 `library/`、`temp/`、`settings/` 和各文件的 `.meta`。`.meta` 和 `settings/` 要提交，前两个已加进 `.gitignore`。
2. 打开或新建任意一个场景，保存（例如叫 `Main`），点上方 ▶ 预览就能玩。
   - **不需要手工搭场景**：游戏启动时如果发现场景里没有 Canvas 或没挂 `Boot`，会用代码自动创建（控制台会打印一条黄色提示）。设计分辨率 750 × 1334（适配屏幕宽度）也由代码设置。
   - 想改启动参数时，再在 Canvas 节点上手动添加组件 `Boot`：
     - `autoPlay` 勾选：每秒自动领宝箱、抽兽、升星、升级、穿装备、闯关、爬塔（会跳过拍符和签到弹窗），用来快速看后期。平时测试请**取消勾选**。游戏里「更多」页签也能开关。
     - `resetSaveOnStart` 勾选：每次预览都从零开始。
3. 菜单 项目 → 项目设置 → 把这个场景设为启动场景（构建发布时需要）。浏览器里用的是模拟广告：URL 后面加 `?ad=skipped`、`?ad=nofill` 可以测试失败分支。
4. 场景文件、`.meta` 和 `settings/` 目前只在你自己电脑上（仓库里没有）。建议提交到仓库，换电脑或重新拉代码时就不会丢。

### 黑屏怎么办

1. 看「资源管理器」里还有没有你的场景（例如 `Main`）：有的话双击打开再预览；没有的话新建一个空场景、保存、预览即可（见上面第 2 步）。
2. 场景、`.meta` 都是没提交的本地文件，`git pull` 本身不会删它们；但用 GitHub Desktop 等工具拉代码时如果选了"暂存（stash）本地改动"，它们会被收进 stash，在命令行运行 `git stash list` 查看，`git stash pop` 恢复。
3. 还是黑屏：浏览器按 F12 看控制台，正常会依次打印 `[Boot] 开始启动`、`[Skin] 已加载 N 张素材`、`[Boot] 启动完成`，把红色报错截图发出来。

### 现身拍符

- **拍符练习**：「更多」页签里的按钮。可以用 ◀ ▶ 切换 20 只异兽，体验各自的现身方式；拍完会显示每一拍离绿区中心多少毫秒，不发奖励、不影响存档。适合找朋友试手感。
- **正式拍符**：在 `Boot` 组件上**取消勾选 autoPlay**。之后十连抽到稀有或传说、遇到野生异兽、Boss 收服、签到领到稀有兽时，会自动弹出拍符界面。勾选 autoPlay 时会自动跳过拍符（按 1 印结算）。
- 拍符界面中间显示异兽立绘，圆环、符箓和特效由代码绘制，代码在 `view/reveal/`；其中可单测的计算在 `RevealGeometry.ts`。

### 清档（从头开始）

任选一种，清档期间会暂停自动存档，不会把旧进度写回去：

- 「更多」页签里的 **清档重开** 按钮，点两次确认（浏览器和手机都能用）；
- 在 Canvas 的 `Boot` 组件上勾选 **Reset Save On Start**，之后每次预览都从零开始（测完记得取消）；
- 浏览器预览时网址后面加 `?reset=1`。

## 构建抖音小游戏

1. 在抖音开放平台创建**小游戏**，拿到 AppID。
2. Cocos Creator → 项目 → 构建发布 → 发布平台选 **抖音小游戏**，填 AppID，设备方向选竖屏，构建。
3. 用抖音开发者工具打开构建输出目录（`client/build/` 下对应抖音的文件夹），预览、真机调试、上传。
4. 首包大小限制、分包规则以抖音开放平台当时的文档为准。首包只放第 1 章资源，后续章节放分包。

## 提审前检查

- [ ] `ads.json` 填好激励视频、插屏的广告位 ID（没填时抖音里会按模拟广告处理，只能用于开发期）
- [ ] `app/App.ts` 的 `RELEASE` 改成对应版本（`mvp0` / `mvp1` …），决定哪些广告位开放
- [ ] `Boot` 组件的 `showDebug`、`autoPlay` 取消勾选
- [ ] 进山界面有「概率说明」入口（游戏设计文档 4.3）
- [ ] 「更多」页的用户协议、隐私政策（`view/more/LegalText.ts`）把【开发者名称】【联系邮箱】【生效日期】【广告服务方名称】换成真实信息，并对照抖音开放平台当时的要求核对
- [ ] 软著名称、游戏名称、主体信息逐字一致（运营文档 2.1）
